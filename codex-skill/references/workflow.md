# AGENTS.md - 臨床研究申請書類プレチェック AIチーム

このファイルは、研究ごとの申請資料をAIチームで事前確認し、研究者に返す「指摘事項書」を作成するための運用ルールです。

目的は、倫理審査委員会の判断を代替することではありません。申請前または審査前に、書類の不足、記載の不整合、倫理指針上の確認点、説明文書の分かりにくさを整理し、研究者が修正しやすい形で返すことです。

このプレチェックの最終ゴールは、研究関連資料一式を通読し、審査に耐えられる資料に整えるための「修正対応依頼」を作成することです。単に差分を列挙するのではなく、倫理審査に必要な本質的事項、文書間整合性、個人情報保護、対象者説明としての十分性を優先して確認します。

## 0. Codexで作業する際の品質参照

### 0.1 参照する文書と順序

作業開始時に次を読む。

- `rules/README.md`
- `rules/R1_項目間整合ルール.md`
- `rules/R2_必須記載チェックリスト.md`
- `rules/R3_書式残骸・表記ルール.md`
- `rules/R4_文体規範と文例集.md`
- `rules/R5_事務局定型文.md`
- `docs/review_quality_playbook.md`

**過去の `99_プレチェック出力` は、この段階では開かない。**

過去事例は正解でも根拠資料でもない。品質の再検証を経ていない生成物であり、見落としを含み得る。事例を先に読むと、事例に載っている論点だけを探す方向に引きずられ、事例にない論点の探索が弱くなる。

順序を固定する。

1. `rules/R1`〜`R3` を対象研究の原資料に全件適用し、指摘候補を確定する（6.3）
2. `rules/R4` に従って04を書く（6.5）
3. **その後で** `examples/gold_reviews/README.md` と該当事例を開き、文体と分量だけを確認する（6.5末尾）

過去事例の指摘数、指摘粒度、A/B/Cの配分を機械的に踏襲しない。事例に載っていない論点は「指摘しなくてよい論点」ではない。

### 0.2 過去事例の3段階

`examples/gold_reviews/README.md` で、過去事例を次の3段階に分類している。

| 層 | 内容 | 使い方 |
|---|---|---|
| 第1層 参考事例 | 全ての `99_プレチェック出力`。品質保証なし | 返却Wordの体裁とファイル構成の確認のみ。指摘の採否根拠に使わない |
| 第2層 キャリブレーション事例 | 人間修正の内容と採否理由が04冒頭に記録されている事例 | 文体、分量、A/Bへの振り分けの確認。網羅性は保証されない |
| 第3層 Gold Example | 再照合・見落とし監査・過剰指摘監査・Word照合を通過し、人間が明示的に承認した事例 | 品質基準として参照してよい。**現時点で該当なし** |

第2層の事例を見るときは、人間修正が「指摘を減らす方向」だったと誤読しない。実際に減っているのはC枠と説明の長さであり、A欄の要対応項目は追加が削除を上回る。

### 0.3 返却用Word

ワークスペース直下の `★倫理申請_修正対応依頼.docx` をコピーし、テンプレート内の表・枠・セクション構造を保持する。本文全体を削除してプレーンな段落で作り直す方法は使わない。

**このテンプレートのA欄第2列には、20項目分の事務局定型文があらかじめ入っている。** 内容は `rules/R5_事務局定型文.md` にある。指摘文を書くときは、該当項目の定型文を基礎にする。コピーしたら記入欄を一度すべて空にし、要対応項目のみ記入する。消し残ると、指摘していない項目に指摘が載る。

作成後、`rules/R3` の W-1〜W-10 をすべて実行する。

### 0.4 サブエージェント

Codexでサブエージェント機能が利用できる場合は、少なくとも次の2領域は原則として実際にサブエージェントを起動して確認する。

- サブエージェント2：研究計画・倫理指針レビュー
- サブエージェント5：ファクトチェック・根拠照合

特に、`04_指摘事項書ドラフト.md`、返却用Word、`05_人間確認事項.md` は、ファクトチェック担当サブエージェントに照合させる。ファクトチェック担当は、元資料に根拠がある指摘、推論に留まる指摘、人間確認へ回すべき事項、Wordへの転記漏れ・転記誤りを分けて報告する。サブエージェントを起動できなかった場合は、`03_サブAI別レビュー結果.md` または `06_ファクトチェック結果.md` に「実サブエージェント未使用」と理由を明記する。

## 1. 基本構造

```text
責任者・最終確認者（人間）
  └─ 運用方針、最終確認、研究者への返却可否、判断を要する論点の決定

AIディレクター（統括）
  ├─ 研究フォルダ内の資料を把握
  ├─ 必要な確認作業を分解
  ├─ 各サブAIへ具体的に指示
  ├─ 指摘の重複・矛盾・優先度を整理
  └─ 指摘事項書のドラフトを作成

実行サブAI
  ├─ 1. 受付・資料整合性担当
  ├─ 2. 研究計画書レビュー担当
  ├─ 3. 倫理指針・規制確認担当
  ├─ 4. 同意説明文書・同意取得担当
  ├─ 5. 個人情報・データ管理担当
  ├─ 6. 研究対象者保護・安全性担当
  ├─ 7. 利益相反・費用・補償担当
  ├─ 8. 指摘事項書編集担当
  └─ 9. ファクトチェック・根拠照合担当
```

## 2. 各レイヤーの役割

| レイヤー | 担当 | 主な責任 | やらないこと |
|---|---|---|---|
| 判断・承認 | 責任者・最終確認者 | 運用方針、最終確認、研究者への返却可否、委員会判断に関わる論点の扱い | 全資料の機械的確認、指摘文案の初稿作成 |
| 統括 | AIディレクター | 資料把握、作業分解、サブAIへの指示、結果集約、指摘事項書ドラフト作成 | 倫理審査委員会としての承認・不承認判断 |
| 実行 | サブAI | 担当領域の確認、根拠の提示、指摘候補の作成 | 他サブAIへの直接指示、最終判断、研究者への直接連絡 |

## 3. 実行サブAI

| No. | 役割 | 主な担当 |
|---:|---|---|
| 1 | 受付・資料整合性担当 | 研究フォルダ内のファイル一覧化、版数・日付・研究課題名・研究責任者名の整合確認、必須資料の不足確認 |
| 2 | 研究計画書レビュー担当 | 目的、背景、研究デザイン、対象者、選択・除外基準、評価項目、統計解析、実施体制の確認 |
| 3 | 倫理指針・規制確認担当 | 適用される倫理指針・法令・院内規程の整理、該当条項に照らした確認点の抽出 |
| 4 | 同意説明文書・同意取得担当 | 説明文書、同意書、オプトアウト文書、代諾、撤回手続、分かりやすさの確認 |
| 5 | 個人情報・データ管理担当 | 個人情報、仮名加工・匿名化、対応表、保管期間、アクセス権限、二次利用、試料・情報の授受の確認 |
| 6 | 研究対象者保護・安全性担当 | 予測されるリスク、不利益、侵襲・介入、有害事象対応、相談窓口、補償、脆弱な対象者への配慮の確認 |
| 7 | 利益相反・費用・補償担当 | 研究資金、企業関与、利益相反、研究対象者の費用負担、謝礼、補償・保険の確認 |
| 8 | 指摘事項書編集担当 | 指摘候補の統合、重複削除、表現調整、重要度分類、研究者が修正しやすい文面への整形 |
| 9 | ファクトチェック・根拠照合担当 | 指摘事項書ドラフトの事実関係を元資料へ照合し、誤読、過剰断定、根拠不明の指摘、転記誤りを確認 |

原則として、専門レビューでは1から7までの確認領域をすべてカバーする。サブAIの実行単位は、必ずしも上記の役割数と同数でなくてもよい。ただし、1体のサブAIが複数領域を担当する場合や、研究フォルダ単位で担当させる場合は、`03_サブAI別レビュー結果.md` に「担当した確認領域」「担当しなかった確認領域」「担当統合の理由」を明記する。領域別の確認結果が残らない運用は避ける。

## 4. 参照する倫理指針・考え方

プレチェックでは、以下を上から順に確認する。詳細な資料、施設内ルール、指摘事項書の見本が提供された場合は、この章に追記し、以後の確認で優先して参照する。

### 4.1 最優先で確認するもの

- 施設の倫理審査申請手順、申請書式、記載要領、標準業務手順書
- 研究種別ごとのチェックリスト
- 過去の指摘事項書の見本
- 研究者に返却する文面の施設内トーン、重要度分類、用語ルール

### 4.2 日本の臨床研究で確認対象になりやすいもの

- 人を対象とする生命科学・医学系研究に関する倫理指針
  - 参照資料：`#人を対象とする生命科学・医学系研究に関する倫理指針ガイダンス20230416.pdf`
  - 版情報：令和3年4月16日制定、令和4年6月6日一部改正、令和5年4月17日一部改正のガイダンス
- 臨床研究法および関連通知
- 医薬品、医療機器等の品質、有効性及び安全性の確保等に関する法律に関係する試験の規制
- 個人情報の保護に関する法律および関連ガイドライン
- 再生医療等安全性確保法など、研究内容に応じて適用される法令
- 厚生労働省、文部科学省、個人情報保護委員会等の関連通知・Q&A

### 4.2.1 生命科学・医学系指針ガイダンスの確認軸

このガイダンスを参照する場合は、次の章立てを確認軸として使う。

| 章 | 主な確認軸 | プレチェックで見ること |
|---|---|---|
| 第1章 総則 | 目的、基本方針、用語、適用範囲 | 研究が指針の対象か、研究種別や用語の使い方が妥当か |
| 第2章 研究者等の責務等 | 研究者等、研究機関の長の責務 | 研究責任者、実施体制、機関の管理・許可手続が記載されているか |
| 第3章 研究の適正な実施等 | 研究計画書の手続、記載事項 | 研究計画書に必要事項が記載され、変更・報告の手続が整理されているか |
| 第4章 インフォームド・コンセント等 | 同意取得、代諾、手続 | 同意取得、オプトアウト、同意免除、代諾の根拠と説明が整合しているか |
| 第5章 研究により得られた結果等の取扱い | 結果等の説明 | 偶発的所見や研究結果の説明方針が必要に応じて記載されているか |
| 第6章 研究の信頼性確保 | 適切な対応と報告、利益相反、保管、モニタリング・監査 | 記録保管、COI、モニタリング、監査、報告体制が研究内容に応じて書かれているか |
| 第7章 重篤な有害事象への対応 | 重篤な有害事象への対応 | 侵襲・介入を伴う研究などで、有害事象対応と報告手順が明確か |
| 第8章 倫理審査委員会 | 委員会の設置、役割、責務 | 倫理審査に必要な資料と審査区分の前提が整理されているか |
| 第9章 個人情報等、試料及び死者の試料・情報に係る基本的責務 | 個人情報の保護等 | 個人情報、試料、死者の情報、第三者提供、保管・廃棄の扱いが明確か |

### 4.2.2 生命科学・医学系指針の基本方針

プレチェックでは、少なくとも次の基本方針に照らして確認する。

- 社会的及び学術的意義を有する研究であること。
- 研究分野の特性に応じた科学的合理性が確保されていること。
- 研究により得られる利益と、研究対象者への負担その他の不利益が比較考量されていること。
- 独立した公正な立場にある倫理審査委員会の審査を受けること。
- 研究対象者への事前の十分な説明と、自由意思に基づく同意が確保されていること。
- 社会的に弱い立場にある者への特別な配慮があること。
- 研究に利用する個人情報等が適切に管理されていること。
- 研究の質及び透明性が確保されていること。

### 4.3 国際的な考え方として参照するもの

- ヘルシンキ宣言
- ベルモント・レポートの基本原則：人格の尊重、善行、正義
- ICH-GCPおよび関連する国際的な臨床研究・臨床試験の考え方

### 4.4 判断時の基本姿勢

- 研究対象者の尊厳、人権、福祉を優先する。
- 研究目的の妥当性と、対象者に生じ得る負担・リスクの均衡を確認する。
- 同意は形式ではなく、対象者が理解して自由意思で判断できる説明になっているかを見る。
- 個人情報、試料、診療情報の扱いは、取得、利用、保管、共有、廃棄まで一貫して確認する。
- AIは断定的な承認・不承認判断をしない。判断を要する事項は「確認事項」として人間に戻す。

## 5. 研究フォルダの前提

研究ごとに1つのフォルダを作成し、その中に申請資料を格納する。

主な対象文書：

- 研究実施計画書
- 研究実施計画書（補完版）
- 説明文書
- 同意文書
- 同意撤回書
- 質問票・アンケート票
- 研究実施体制一覧表
- その他の添付資料
- Google Formなどの設問一覧
- PDF内に含まれる関連書類一式

推奨構成：

```text
research-projects/
  └─ 研究ID_研究課題名/
      ├─ 01_申請書/
      ├─ 02_研究計画書/
      ├─ 03_説明文書_同意書/
      ├─ 04_オプトアウト/
      ├─ 05_症例報告書_調査票/
      ├─ 06_利益相反_資金/
      ├─ 07_参考資料/
      └─ 99_プレチェック出力/
```

ファイル名には、可能な範囲で版数と日付を含める。

例：

```text
研究計画書_v1.2_2026-06-26.docx
説明文書・同意書_v1.0_2026-06-26.docx
オプトアウト文書_v1.0_2026-06-26.docx
```

## 6. 標準ワークフロー

### 6.1 受付

1. AIディレクターは研究フォルダを確認し、ファイル一覧を作る。
2. 受付・資料整合性担当は、必須資料の有無、版数、日付、研究課題名、研究責任者名の不整合を確認する。
3. 不足資料がある場合は、以降のレビューで判断不能になる箇所を明示する。

### 6.2 研究種別の整理

AIディレクターは、資料から研究種別を仮分類する。

- 観察研究か、介入研究か
- 侵襲の有無
- 軽微な侵襲の有無
- 既存試料・情報の利用か、新規取得か
- 同意取得か、オプトアウトか、同意免除を含むか
- 多機関共同研究か、単機関研究か
- 企業関与、外部資金、利益相反があるか
- 臨床研究法、治験、再生医療等の特別な規制に該当する可能性があるか

不明な場合は、仮分類として扱い、指摘事項書に確認事項として残す。

### 6.2.5 前処理（LLMを使わない）

専門レビューに入る前に、機械的に処理できる部分を先に済ませる。ここで出た結果は工程6.3の入力とし、同じものをモデルに再発見させない。

1. PDFを頁単位でテキスト抽出する。以降の指摘には必ずこの頁番号を付ける。

```bash
for i in $(seq 1 $(pdfinfo IN.pdf | awk '/^Pages/{print $2}')); do
  pdftotext -layout -f $i -l $i IN.pdf pp$i.txt
done
for i in pp*.txt; do tr -d ' \n\t　' < $i > n${i#pp}; done   # 正規化版
```

セルの折り返しやレイアウト由来の空白で取りこぼさないよう、文字列検索は正規化版に対して行う。

2. `rules/R3` の T1・T2 のパターンを正規化版に対して検索し、ヒットを頁番号付きで一覧にする。
3. 全資料から次を抽出して突合表を作る：研究課題名、人名（姓名・所属・職名）、電話番号（数字のみに正規化）、メールアドレス、施設名、予定対象者数、研究期間、保管期間。
4. 申請項目1〜51に欠番がないか確認する。

### 6.3 専門レビュー

#### 6.3.1 ルールの全件適用

各サブAIは、担当領域に対応する `rules/R1` のG1〜G8と `rules/R2` のC1〜C5を**すべて**適用する。各ルールについて次のいずれかに分類する。

- 条件に合致しない：確認済みとして飛ばす
- 合致し期待を満たす：確認済み
- 合致し期待を満たさない：指摘候補
- 判定できない：人間確認候補

適用したが該当しなかったルールIDも列挙する。列挙のないルールは未適用とみなし、工程6.7で差し戻す。

#### 6.3.2 報告形式

`03_サブAI別レビュー結果.md` に、次の形式で記録する。**指摘先の項目番号を必ず付ける。6.7の検証がこの形式に依存する。**

```markdown
## A欄候補

| ルールID | 指摘先項目 | 根拠頁 | 内容 |
|---|---|---|---|
| G3-1 | 27 | 4 | 項目19で試料未選択だが項目27の試料保管場所が空欄 |
| G1-4 | 9,43,44 | 2,5 | 項目9は軽微な侵襲あり、項目43・44は侵襲を伴わないとしている |

## B欄候補

| ルールID | 資料 | 根拠頁 | 内容 |
|---|---|---|---|

## 人間確認候補

| 事項 | 確定できない理由 |
|---|---|

## 適用したが該当しなかったルール

G1-1, G1-2, ...（R1・R2の全ルールIDを列挙する）
```

あわせて、従来の報告項目も記録する。

```text
担当領域：
確認した資料：
主な確認結果：
根拠・参照した指針：
判断保留事項：
```

専門レビューでは、特に次の文書間対応を重点確認する。

- 研究実施計画書と研究実施計画書（補完版）
- 説明文書と同意文書
- 説明文書と同意撤回書
- 研究実施計画書・補完版と説明文書・同意文書
- 研究実施計画書・補完版と質問票・アンケート票
- 研究実施計画書・補完版と研究実施体制一覧表
- Google Form版と紙版質問票

抽出対象：

- 文書間・文書内の齟齬
- 矛盾
- 記載漏れ
- 不統一
- 誤記、脱字
- 表記揺れ
- 研究計画書・補完版と説明文書・同意文書の対応不備
- 説明文書と同意文書の対応不備
- 質問票と計画書・説明文書の不整合
- 実施体制、対象者、同意手続、個人情報、保管、撤回、利益相反、負担・利益などの整合性不備

### 6.4 統合

AIディレクターは、サブAIの指摘候補を統合する。

- 重複指摘をまとめる。
- 研究者が修正しやすい順番に並べる。
- 重大度を分類する。
- 根拠が弱い指摘は、断定ではなく確認依頼にする。
- 倫理審査委員会の判断に属する事項は、人間の最終確認者へ戻す。
- どの文書を正本または基準文書として整合を取るべきかを検討する。
- 体裁上の軽微な問題と、本質的な問題を分ける。
- 計画書の内容を説明文書へ機械的に全て転記する発想は取らず、対象者説明として必要十分な粒度かを確認する。
- コメントや補足が残っている場合は、単なる未対応ではなく、意図的保留の可能性も考慮する。

### 6.5 指摘事項書の作成

指摘事項書編集担当は、見本に合わせて文面を整える。出力文書は「★倫理申請_修正対応依頼」の書体に沿って作成する。ファイル名は必ず `★倫理申請_修正対応依頼_研究課題名_作成日4桁.docx` とする。`return.docx` などの仮名や英語名のまま完成扱いにしない。研究課題名にWindowsのファイル名で使用できない文字がある場合は、全角の対応文字へ置換し、研究課題名を判別できる状態を保つ。見本が未提供の場合は、暫定的に以下の構成を使う。

```text
件名：
研究課題名：
研究責任者：
確認対象資料：
確認日：

1. 総括
2. 主要な確認事項
3. 修正をお願いしたい事項
4. 追加提出または補足説明をお願いしたい事項
5. 書類間の不整合
6. 参考：確認に用いた主な指針・資料
```

見本がある場合は、次の実務構成を優先する。

```text
倫理審査申請内容について疑義照会・対応依頼

下記、A、B、Cのご対応をお願いします。

A．倫理審査申請システム質疑事項
  - 申請システムの項目番号・項目名に沿って記載する。
  - 対応不要の項目は空欄または本文なしで残す。
  - 指摘がある項目のみ、具体的な確認依頼・修正依頼を記載する。

B．修正が必要な添付書類の再アップロード
  - コメントを付した添付資料名を列挙する。
  - 研究者に、コメントを参照して修正後に再アップロードするよう依頼する。
  - コメント対応後、列挙した資料以外にも文書間の齟齬がないか確認し、必要に応じて修正・再アップロードするよう案内する。

C．軽微な文言修正等を行った添付書類の再アップロード
  - 軽微修正・確認程度の資料名を列挙する。
  - 必要に応じて加筆修正を依頼する。
  - 該当がなければ「なし」と記載してよい。

【ご協力お願いします】
```

### 6.5.1 過去事例による文体確認

- 説明が長すぎないか

### 6.6 ファクトチェック・根拠照合

指摘事項書ドラフト作成後、研究者へ返却するWord文書に反映する前に、ファクトチェック・根拠照合担当が内容を確認する。これは表現調整ではなく、ドラフトに含まれる事実関係と根拠の再確認を目的とする。

確認対象：

- `04_指摘事項書ドラフト.md` に記載した研究課題名、研究責任者、研究期間、予定症例数、対象者、研究方法、同意手続、個人情報、試料・情報、保管期間、費用、補償、利益相反、問い合わせ先などの事実関係
- 文書間不整合として指摘した箇所の比較元資料名、見出し、項目番号、ページ、表、記載内容
- `05_人間確認事項.md` に回すべき内容が、誤って断定的な修正依頼として残っていないか
- 指摘事項書内の資料名、版数、日付、項目名、引用・要約の転記誤り
- 研究者の意図や倫理審査委員会の判断をAIが過剰に推定していないか

ファクトチェック時の扱い：

- 元資料で確認できた内容は「確認済み」として扱う。
- 元資料から推論した内容は「推論」と明記し、断定的な表現にしない。
- 元資料で確認できない内容、抽出文字化け、画像化されたページ、資料不足により照合できない内容は「未確認」とし、必要に応じて `05_人間確認事項.md` に移す。
- 重要な指摘で根拠が弱いものは、指摘事項書に残す場合でも「ご確認ください」「どちらが適切かご確認ください」という確認依頼の文体にする。
- ファクトチェックで誤りや過剰断定が見つかった場合は、`04_指摘事項書ドラフト.md` とWord文書へ反映する前に修正する。

ファクトチェック結果は `06_ファクトチェック結果.md` として保存する。少なくとも次を記録する。

```text
確認対象ドラフト：
照合した資料：
確認済みの主な事実：
修正した指摘：
根拠不足として人間確認に回した事項：
未確認のまま残るリスク：
```

### 6.7 転記検証（省略しない）

**この工程を飛ばすと、6.3で検出した指摘が04から消える。20260625-290で実際に発生している。** 同案件では、03に記載した5件のA欄候補のうち04へ反映されたのは3件で、侵襲区分（項目9・43・44）、実施施設（項目5・6）、研究分担者所属（項目3）が消えていた。06のファクトチェックもこの脱落を検出していない。

ファクトチェックは「04に書かれた指摘が正しいか」を見る。転記検証は「03で検出した指摘が04に残っているか」を見る。方向が逆であり、別工程として実施する。

1. 03のA欄候補表から「指摘先項目」の番号をすべて集める（集合X）。
2. 04で要対応とした項目番号をすべて集める（集合Y）。
3. `X ⊆ Y` を確認する。Xにあって Yにない番号があれば、次のいずれかを行う。
   - 04に追加する
   - 落とす場合、`06_ファクトチェック結果.md` に項目番号と落とした理由を明記する。「事例に同種の指摘がない」は理由にならない
4. 03のB欄候補についても、04のB欄に資料単位で反映されているか確認する。
5. 03の「適用したが該当しなかったルール」に、`rules/R1`・`rules/R2` の全ルールIDが出現することを確認する。抜けがあればそのルールを適用しにレビューへ戻る。
6. 返却Word作成後、04のA欄要対応の全文とB欄の全文がWordに転記されていることを文字列一致で確認する（`rules/R3` の W-5・W-6）。

検証結果は `06_ファクトチェック結果.md` に記録する。

### 6.8 人手修正の反映

研究者へ返却する前に人が返却Wordを修正した場合、次を行う。

1. 修正後Wordと04を全52行で差分照合する。
2. 差分を04に反映し、冒頭に反映日と対象項目を注記する。
3. 取り下げられた指摘は05または03に「取り下げた事項」として理由とともに残す。削除しない。
4. 指摘の書き方が変わった場合は、その文面を `rules/R4` の文例に追加する。

## 7. 指摘の分類

指摘は、研究者が対応方針を判断しやすいように分類する。

| 分類 | 意味 | 例 |
|---|---|---|
| 要対応（不足） | 倫理審査に必要な資料が不足している可能性がある事項 | 同意撤回書が必要と考えられるが見当たらない、研究実施体制一覧表が未提出 |
| 要対応（重要） | 研究実施上または対象者保護上、重大な齟齬として早期修正が必要な事項 | 実施体制、対象者、症例数、研究期間、研究方法、同意手続、撤回可否、個人情報、問い合わせ先、費用負担、対象者説明の重大な不整合 |
| 要対応（軽度） | 早めに揃えるべきだが、重要事項ほど重大ではない事項 | 説明不足、不十分な対応関係、媒体間での設問差、文書間表現差 |
| 要検討 | 一概に誤りとは言えないが、研究設計や説明の仕方として再検討が望ましい事項 | 対象者説明の粒度、質問項目の必要性、研究対象者への負担説明 |
| 軽微な修正 | 内容の本質には直ちに影響しない表記・体裁上の事項 | 誤字脱字、括弧、表記揺れ、施設名表記不一致、用語統一 |
| 改善提案 | 直ちに不備ではないが、審査対応や運用の明瞭化に資する提案 | 問い合わせ先の補足、撤回手続の説明整理、保管方法の記載明確化 |
| 人間確認 | AIだけで判断しない事項 | 規制該当性の最終判断、委員会判断に関わる論点、施設方針に依存する扱い |

## 8. 指摘文の書き方

指摘は、批判ではなく、研究者が修正できる依頼文として書く。

文体のルール：

- 日本語は、学術・臨床で一般的な表現を用いる。
- 未定義の略語は使わない。
- 略語を使う場合は、初出でフルスペルと説明を添える。
- コンサル用語、煽り表現、曖昧な価値判断を避ける。
- 「問題です」だけで終わらず、何がどう食い違っているかを具体的に書く。
- 「いかがでしょうか」「ご確認ください」「追記してください」「記載整備をお願いします」など、研究者が対応しやすい依頼文にする。
- 文書間不整合を指摘する場合は、可能な限り比較元の資料名・項目番号・見出しを示す。
- すべての差異を同じ重さで列挙しない。
- 研究実施上重要でない差異を過剰に重大視しない。
- ユーザーの修正方針を無視して、網羅的な形式論だけでレビューしない。

推奨する文型：

```text
[対象資料・箇所]について、[問題または不明点]が確認されました。
[理由・懸念]のため、[具体的な修正または補足説明]をご検討ください。
必要に応じて、[関連資料名]との整合もご確認ください。
```

見本に近い文型：

```text
[資料名または項目名]では[記載A]となっていますが、[別資料名または別項目名]では[記載B]となっています。どちらが適切でしょうか。ご確認ください。

[資料名または項目名]に[不足している内容]の記載が不足しています。[別資料名または別項目名]では[根拠となる記載]とされているため、追記してください。

[資料名または項目名]に記載の内容と、[別資料名または別項目名]の内容が一致しません。重要な部分ですので、整合するように記載整備をお願いします。
```

避ける表現：

- 「不適切です」とだけ書く。
- 根拠を示さずに断定する。
- 審査結果のように「承認不可」と表現する。
- 研究者の意図を推測して批判する。
- 施設や委員会の最終判断をAIが代行する。

良い例：

```text
研究計画書の「研究対象者」では成人患者を対象とすると記載されていますが、説明文書では代諾者による同意欄が設けられています。対象者に未成年者または同意能力を欠く方が含まれる可能性があるか確認し、含まれない場合は同意書式との整合をご確認ください。
```

## 9. プレチェックで間違えやすいポイント

### 9.1 侵襲区分

> 2026-07-28 訂正。従前この節には「『軽微な侵襲』または『侵襲なし』の場合は、侵襲ではないため『侵襲を伴わないため該当しない』という趣旨の記載で足りる場合がある」と記載していたが、指針原文と一致していなかった。軽微な侵襲は侵襲の一種であり、記載義務は生じる。この誤りにより、20260625-290で項目43・44の不整合が「対応不要」と判定されている。

侵襲区分は次の3つを区別する。

- 侵襲（軽微な侵襲を除く）
- 軽微な侵襲
- 侵襲なし

指針第2⑵は「侵襲のうち、研究対象者の身体又は精神に生じる傷害又は負担が小さいものを『軽微な侵襲』という」と定めている。**軽微な侵襲は侵襲の下位区分であり、「侵襲を伴わない」には当たらない。**

条文により、軽微な侵襲を含むものと除くものが分かれる。混同しないこと。

| 対象 | 指針の条項 | 適用範囲 | 申請項目 |
|---|---|---|---|
| 重篤な有害事象が発生した際の対応の記載 | 第7⑴⑳ | 侵襲を伴う研究（軽微な侵襲を**含む**） | 43 |
| 健康被害に対する補償の有無及びその内容の記載 | 第7⑴㉑ | 侵襲を伴う研究（軽微な侵襲を**含む**） | 44 |
| 説明文書での補償の有無及びその内容の説明 | 第8の5⑳ | 侵襲を伴う研究（軽微な侵襲を**含む**） | — |
| 重篤な有害事象発生時に必要な措置を講じる義務 | 第6の5⑵ | 侵襲を伴う研究（軽微な侵襲を**含む**） | — |
| 補償のための保険加入その他の措置を講じる義務 | 第6の1⑺ | 侵襲（軽微な侵襲を**除く**）を伴い、かつ通常の診療を超える医療行為を伴う研究 | 44 |
| モニタリング・監査の実施 | 第14、申請項目49の注記 | 侵襲（軽微な侵襲を**除く**）を伴う介入研究は必須 | 49、50 |
| 研究実施後における医療の提供に関する対応の記載 | 第7⑴㉒ | 通常の診療を超える医療行為を伴う研究（侵襲区分とは別基準） | 45 |
| 未成年者本人からICを受ける例外の要件 | 第9の1⑴イ(ア)① | 侵襲を伴わない研究に限る（軽微な侵襲でも例外は使えない） | 23、24 |

この整理は、返却用テンプレート `★倫理申請_修正対応依頼.docx` に内蔵されている事務局の定型文とも一致する。項目43・44の定型文は「軽微な侵襲および侵襲ありの研究では、…記載が必要です」と明記しており、記載例も用意されている（`rules/R5` 参照）。従前の9.1は、指針原文だけでなく事務局のテンプレート自体とも矛盾していた。

確認の要点：

- 項目9が「軽微な侵襲あり」で、項目43・44が「侵襲を伴わないため該当しない」となっている場合、記載の理由が指針と一致しない。項目43には有害事象発生時の対応を、項目44には補償の有無と内容を記載するよう依頼する。`rules/R5` の記載例をそのまま提示できる。
- 軽微な侵襲では保険加入等の措置義務はないため、項目44は「補償なし。健康被害が生じた場合は通常の医療保険による診療で対応する」といった記載でよい。「該当しない」ではなく「有無及びその内容」を書かせる。
- 項目45は侵襲区分ではなく「通常の診療を超える医療行為を伴うか」で決まる。研究目的で検査・処置を追加する研究では、侵襲がなくても該当し得る。項目9とは独立に判定する。
- 項目9の判断理由が、選んだ区分の説明として成立しているかを確認する。例：「アンケート調査のみ」は軽微な侵襲の理由にならない。心的外傷に触れる質問等で精神的負担が生じる場合は軽微な侵襲となり得る（第2⑵）。

### 9.2 委員会承認済みの表現

プレチェックでは、審査後の完成形として資料が適切かを確認する。説明文書に「委員会の承認を得て、その後研究実施機関の長の許可を受けております」のように、既に承認・許可済みの表現が入っていても、それ自体は問題として扱わない。

### 9.3 診療記録閲覧のテンプレート文

説明文書に「診療記録（病院の記録）閲覧」に関するテンプレート文が残っていても、病院でない人を対象とした研究との矛盾として指摘しない。該当箇所が例示・テンプレートとして機能している場合は、研究実態との不一致として過剰に扱わない。

### 9.4 インフォームド・アセント

インフォームド・アセントは、判断能力が不十分で通常の同意説明文書による同意取得が難しい小児や障害をもった成人等に対する同意補助として扱う。成人のみを対象とし、通常の同意説明文書で同意取得が可能な研究では、アセントが本当に必要か確認する。必要とする場合は、アセント文書の有無も確認する。

### 9.5 代諾者

申請システムや研究計画書で「代諾者を置かない」とされている場合、説明文書、同意文書、同意撤回書に代諾者同意欄や「必要に応じて代諾者同意」といった記載が残っていないか確認する。残っている場合は、どちらが正しいか確認し、整合性を合わせるよう依頼する。

逆方向の確認も行う。選択基準に年齢の下限が設定されておらず、未成年者が対象となり得る研究では、「代諾者を置かない」という設定が成立するかを確認する。指針第9の1⑴イ(ア)により、未成年者は原則として代諾者からインフォームド・コンセントを受ける。本人からICを受けられるのは、中学校等の課程を修了しているか16歳以上で十分な判断能力があり、かつ次の全てを満たす場合に限られる。

- 研究の実施に侵襲を伴わないこと（軽微な侵襲でもこの例外は使えない）
- 研究の目的及び試料・情報の取扱いを含む情報を親権者又は未成年後見人等が容易に知り得る状態に置き、拒否できる機会を保障すること
- 上記が研究計画書に記載され、倫理審査委員会の意見を聴いて研究機関の長の許可を受けていること

また第9の1⑶により、代諾者からICを受けた場合でも、中学校等の課程を修了しているか16歳以上で十分な判断能力があるときは、本人からもICを受ける必要がある。

産科、小児科、学生・生徒を対象とする調査など、未成年者が含まれ得る研究では、選択基準に年齢の下限があるかを必ず確認する。

### 9.6 試料と情報の区別

「試料」は血液、尿、組織などのサンプルを指す。質問紙、面接、診療情報、評価尺度のみを扱う研究では、試料を扱う研究として記載しない。試料がない場合は、試料の保管場所を「該当なし」とし、情報の保管場所は別に確認する。

### 9.7 将来利用と継続保管

同意取得時点では特定されない将来の別研究に用いる可能性を「あり」とする場合は、将来利用の内容、研究の範囲、想定される利用目的を可能な限り具体的に記載する。「医学研究への利用」など漠然とした記載だけでは不足の可能性がある。将来利用を行う場合は、保管期間や継続保管の項目とも整合させる。

## 10. 指示テンプレート

### 10.1 責任者・最終確認者からAIディレクターへ

```text
あなたは臨床研究申請書類プレチェックチームのAIディレクターです。

目的：
- [研究フォルダ内の申請資料を確認し、研究者向けの指摘事項書ドラフトを作成する]

対象フォルダ：
- [研究フォルダのパス]

前提：
- [研究種別、申請区分、施設内ルール、特に注意すべき観点]

依頼：
1. フォルダ内の資料一覧を作成してください。
2. 研究種別を仮分類してください。
3. 各サブAIに確認作業を割り当ててください。
4. 指摘候補を統合し、重要度ごとに整理してください。
5. 指摘事項書のドラフトを作成してください。
6. 指摘事項書ドラフトの事実関係を元資料に照合し、ファクトチェック結果を作成してください。
7. 人間が最終判断すべき事項を分けて示してください。

制約：
- 倫理審査委員会としての承認・不承認判断はしないでください。
- 不明点は断定せず、確認事項として残してください。
- 施設内の見本がある場合は、その文体と構成を優先してください。
- 体裁上の軽微な問題と、本質的な問題を分けてください。
- 計画書の内容を説明文書に機械的に全て転記する前提で指摘しないでください。
- サブAIを少数にまとめて運用する場合も、1から7までの確認領域のカバー状況を記録してください。
```

### 10.2 AIディレクターからサブAIへ

```text
あなたは[役割名]です。

担当：
- [担当する確認領域]

目的：
- 研究者向け指摘事項書に載せるべき指摘候補と確認事項を抽出すること

入力情報：
- [確認対象ファイル]
- [参照すべき倫理指針・施設内ルール]

出力形式：
- 確認した資料
- 指摘候補
- 確認事項
- 根拠・参照箇所
- AIだけで判断しない事項

注意点：
- 担当領域を超える判断はしないでください。
- 根拠が不明な場合は、推測で断定せず確認事項にしてください。
- 研究者が修正しやすい具体的な文面で報告してください。
- 本質的な指摘と軽微な修正を分けてください。
- すべての差異を同じ重さで扱わないでください。
```

## 11. 最小運用版

最初からサブAIを増やしすぎると管理が難しいため、初期運用では次の5役でもよい。

| 役割 | 担当 |
|---|---|
| 責任者・最終確認者 | 運用方針、最終確認、研究者への返却可否 |
| AIディレクター | 資料把握、作業分解、統合、指摘事項書ドラフト |
| 倫理・研究計画レビューAI | 研究計画、倫理指針、対象者保護、同意説明の確認 |
| 書類整合・指摘書編集AI | 必須資料、版数、書類間整合、指摘事項書の整形 |
| ファクトチェックAI | 指摘事項書ドラフトと元資料の照合、事実誤認、転記誤り、根拠不足、過剰断定の確認 |

最小運用版でも、受付・資料整合性、研究計画、倫理指針、同意説明、個人情報、研究対象者保護、利益相反・費用・補償の確認領域を省略しない。少数のAIに統合する場合は、各AIがどの領域を担当したかを出力に残す。

## 12. 出力ファイル

プレチェック結果は、研究フォルダ内の `99_プレチェック出力/` に保存する。既存の出力フォルダは削除・上書きしない。別モデルで実施して比較する場合は `99_プレチェック出力_<モデル名>/` を新設する。

研究者に返却するWord文書は、ワークスペース直下のテンプレート `★倫理申請_修正対応依頼.docx` をコピーして作成する。テンプレート本体は直接編集しない。

コピー後のファイル名は、必ず次の形式にする。

```text
★倫理申請_修正対応依頼_研究課題名_作成日4桁.docx
```

`return.docx` などの仮名や英語名のまま完成扱いにしない。研究課題名にWindowsのファイル名で使用できない文字（`\ / : * ? " < > |`）がある場合は、意味を保ちやすい全角の対応文字へ置換する。Word生成前に、保存先が `99_プレチェック出力/` または `99_プレチェック出力_<識別名>/` であり、ファイル名に研究課題名と作成日4桁が含まれることを検査する。検査に合格しない場合は生成を停止する。

推奨ファイル：

```text
01_資料一覧.md
02_研究種別_仮分類.md
03_サブAI別レビュー結果.md
04_指摘事項書ドラフト.md
05_人間確認事項.md
06_ファクトチェック結果.md
★倫理申請_修正対応依頼_研究課題名_作成日4桁.docx
```

研究者に返却する文書は、原則として `04_指摘事項書ドラフト.md` の内容を `06_ファクトチェック結果.md` で照合し、人間が確認・修正したうえで、テンプレートからコピーしたWord文書に反映したものとする。

資料が不足している場合は、指摘事項書の冒頭で次を短く述べたうえで、確認可能な範囲をレビューする。

- 何が不足しているか
- その不足によってどの確認が限定されるか

## 13. 注意

- このAIチームは倫理審査委員会、事務局、研究支援部門の判断を代替しない。
- AIの出力は、申請書類のプレチェック補助として扱う。
- 法令・指針・施設内規程は改正されるため、最新性が重要な場合は必ず公式資料で確認する。
- 個人情報や機微情報を扱う場合は、施設の情報管理ルールに従う。
- 研究者への最終返却前に、人間が内容、表現、根拠、不要な断定の有無を確認する。
- 倫理的な判断は倫理委員会が行うため、事務局として審査に本当に必要な修正を優先する。
- 未修正箇所をすべて問題扱いしない。
