## 過去事例との関係

ルールは、対象研究の原資料に対して直接適用する。過去の `99_プレチェック出力` に同種の指摘があるかどうかで採否を決めない。

過去事例を参照するのは、04を書き終えた後、文体と分量を確認する段階だけである。分類と参照順序は `examples/gold_reviews/README.md` にある。

## 作成の経緯

`research-folder/プレチェック完了` 配下の16案件・33版の `04_指摘事項書ドラフト.md`（要対応112件）と、`20260625-290` のCodex版・Claude版・人手修正の差分から抽出した。

作成の動機は、20260625-290で次の3種類の欠落が観測されたことによる。

1. **転記の欠落**：Codex版の03で検出した5件のA欄候補のうち、04に反映されたのは3件だった。侵襲区分（項目9・43・44）、実施施設（項目5・6）、研究分担者所属（項目3）が消えていた。06のファクトチェックもこれを検出していない。
2. **規制解釈の誤り**：`AGENTS.md` 9.1が「軽微な侵襲の場合は『侵襲を伴わないため該当しない』で足りる場合がある」としていたが、指針第7⑴⑳㉑はいずれも「侵襲を伴う研究」であり軽微な侵襲を含む。この誤りにより項目43・44が「対応不要」と判定された。9.1は2026-07-28に訂正済み。
3. **検査の型の欠落**：項目16の相互参照の空転、項目13の年齢下限、項目15の解析対象集団の定義、項目27の保管場所の不一致などが検出されていない。いずれも固定ルールで拾えるものであり、推論力の差ではない。

R1〜R3は3を、`AGENTS.md` 6.7は1を、`AGENTS.md` 9.1の訂正は2を扱う。

作成の過程で、4つ目の欠落が判明した。

4. **事務局定型文が使われていなかった**：返却用テンプレート `★倫理申請_修正対応依頼.docx` のA欄には、20項目分の事務局定型文があらかじめ入っている。テンプレートをコピーして記入欄をすべて空にする運用のため、この文面が読まれないまま捨てられていた。`R5_事務局定型文.md` として抽出した。項目43・44の定型文は「軽微な侵襲および侵襲ありの研究では、…記載が必要です」と明記しており、上記2の誤りはテンプレート自体とも矛盾していた。

## GitHubへの公開について

`rules/` はGitHubリポジトリに含まれる。次を記載しない。

- 研究者、研究対象者、事務局担当者の氏名
- 電話番号、メールアドレス、住所
- 特定の研究の内容が推測できる記述

研究番号（`20260625-290` 等）と、指摘の型を示すのに必要な範囲の記述は記載してよい。既存の `docs/` および `examples/` と同じ扱いである。

具体例を書く必要があるときは、「研究分担者1名の所属が申請書と不一致」のように、氏名を伏せた形にする。

## 更新のしかた

ルールブックは人手修正から育てる。返却Wordを人が直したら、必ず `AGENTS.md` 6.8を実行する。

- 新しい種類の指摘が加わった → R1またはR2に行を追加し、実績件数を1にする
- 指摘の書き方が変わった → R4の文例に追加する
- 指摘が過剰と判断され取り下げられた → R2で「参考」へ降格する。削除はしない（判断の履歴を残す）
- 新しいテンプレート残骸・旧名称が見つかった → R3のT1・T2に追加する
- 規制の解釈に誤りが見つかった → 指針の条項番号を確認したうえで訂正し、訂正前の記述と誤りの影響範囲を残す
- 指摘が過剰と判断された → 発生源となったR1〜R4の条件と要求粒度を訂正し、負例の回帰テストを追加する。単に当該案件から削除するだけで終えない

各ファイル末尾の更新履歴に日付と変更内容を記録する。

## 効果の測り方

`research-folder/プレチェック完了` の33版を回帰テストに使える。各版の04で要対応とした項目番号の集合を正解とし、ルールブックを与えたモデルで再実行して再現率を測る。ルールを変えたら再測定する。

正解ラベルとして使いやすいのは、ファイル冒頭に「研究者へ実際に返却した手修正後の最終Wordに整合させた確定版」と注記のある版である。人手修正後の内容が反映されているため、過剰検出も測定できる。

ただし、これらの版も網羅性の監査は経ていない。再現率が100%でも見落としがないことは示さない。`examples/gold_reviews/README.md` の第3層が空である理由もこれである。
