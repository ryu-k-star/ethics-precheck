# ethics-precheck

臨床研究申請書類のプレチェックを、Codexで安定した方針・手順・品質で実施するための運用リポジトリです。

このリポジトリは、研究資料そのものを保存する場所ではありません。研究ごとのPDF、Word、抽出テキスト、プレチェック結果はローカル作業用として扱い、GitHubにはアップロードしません。

## 目的

- 申請資料の不足、文書間不整合、倫理指針上の確認点、説明文書の分かりにくさを整理する。
- 倫理審査委員会の判断を代替せず、研究者が修正しやすい「修正対応依頼」を作成する。
- どの研究が来ても、同じ確認方針、同じ手順、安定した品質でプレチェックできるようにする。

## GitHubに保存するもの

- `AGENTS.md`

- `docs/`

- `codex-skill/`（Codexユーザースキルとして配布する英数字パス版）
- `★倫理申請_修正対応依頼.docx`
- `.gitignore`
- `README.md`

## GitHubに保存しないもの

- `research-folder/`
- `tmp/`
- 研究ごとのPDF、Word、申請資料
- 研究ごとの抽出テキスト
- 研究ごとの `99_プレチェック出力/`
- 研究内容を埋め込んだ一回限りの生成スクリプト

## 基本運用

1. 新しい研究フォルダを `research-folder/` に置く。
2. Codexは `AGENTS.md`、`rules/R1`〜`R4`、`docs/review_quality_playbook.md` を読む。この時点で過去の `99_プレチェック出力` は開かない。
3. 前処理（頁単位のテキスト抽出、書式残骸の検索、値の突合表）を行う。
4. `rules/R1`〜`R3` を全件適用し、指摘候補を確定する。適用したが該当しなかったルールIDも記録する。
5. `rules/R4` に従って `04_指摘事項書ドラフト.md` を書く。
6. その後で `examples/gold_reviews/README.md` の第2層事例を開き、文体と分量を確認する。指摘は削らない。
7. 転記検証を行う。03のA欄候補が04にすべて反映されていることを確認する。
8. 返却用Wordは `★倫理申請_修正対応依頼.docx` をコピーして作成し、テンプレートの表・枠を保持する。コピー先は `99_プレチェック出力/★倫理申請_修正対応依頼_研究課題名_作成日4桁.docx` とし、仮名・英語名のまま完成扱いにしない。
9. 人が返却Wordを修正した場合、差分を04へ反映し、`rules/` を更新する。
10. プレチェック完了後、研究資料や研究フォルダはローカル運用に従って削除・入れ替えする。

## Codexスキル版

`codex-skill/` は、同じルール、品質プレイブック、Wordテンプレート、汎用スクリプトをCodexスキルとして配布するためのパッケージです。内部の参照ファイルとテンプレートは英数字名ですが、研究者へ返却するWordは必ず日本語名 `★倫理申請_修正対応依頼_研究課題名_作成日4桁.docx` で生成します。英語名はスキル内部だけで使用します。

## ルールブック

`rules/` に、何と何を突合するかを列挙したルールを置く。散文の指示では検査が抜けるため、ID付きで管理する。

| ファイル | 内容 |
|---|---|
| `R1_項目間整合ルール.md` | 申請51項目と補完版・説明文書・同意書式の間で突合する組み合わせ（G1〜G8） |
| `R2_必須記載チェックリスト.md` | 記載の欠落を探す検査（C1〜C5）。必須／条件付き必須／参考の3段階 |
| `R3_書式残骸・表記ルール.md` | 文字列検索で拾うテンプレート残骸・旧名称・表記ゆれ（T1〜T4）、返却Wordの自己点検（W-1〜W-11） |
| `R4_文体規範と文例集.md` | 指摘文の構造、使う語・使わない語、項目別の文例 |
| `抽出根拠.md` | 各ルールの出典案件と件数 |

ルールブックは人手修正から育てる。返却Wordを人が直したら、必ず `AGENTS.md` 6.8を実行する。

## 注意

このリポジトリをprivateで運用してください。研究資料を誤ってコミットしないため、`.gitignore` で研究フォルダと一時ファイルを除外しています。
