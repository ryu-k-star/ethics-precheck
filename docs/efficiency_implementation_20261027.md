# プレチェック使用量削減の実装記録（2026-10-27）

## 追加改善：案件の保存ファイルを削減

通常は返却Wordと `_internal/review_state.json` の計2ファイル、人間確認がある場合だけ `確認事項.md` を加えた計3ファイルとする方式を既定に変更した。内部データは一つの構造化記録へ集約し、各担当は必要な記録を一度だけ返す。担当別報告書、03/04/06等のMarkdown、検証報告書は通常保存しない。従来の検証に必要な表はプログラムで一時生成し、処理後に除去する。人間が読む必要のない内部データは `_internal/` に置く。

根拠照合へ渡す内容も、確定指摘・原文・期間・人間確認・実Wordの記入欄を中心にし、全108規則の結果表と全52行ドラフトの重複入力を省いた。原文と規則の全件確認、指摘の脱落防止、全行転記検証は維持する。旧案件のファイルは移動・削除しない。以下の多ファイル構成の説明は互換処理の説明として残し、通常の実行は現行v3手順に従う。

## 実装した内容

1. 原資料の抽出を再利用し、原文を省略せず資料名・頁・行範囲・識別子で取得できる索引を追加した。
2. R1/R2の全108規則を群単位で割り当て、補足・例外を含む原文のまま担当入力へ組み込む処理を追加した。R3の機械検出結果と事実候補も渡す。R4/R5は編集段階で共通規範と該当項目のみを渡す。
3. 全原文を少なくとも1担当へ渡し、一致しない原文も除外しない。PDF/Wordの目視、非対応形式の人間確認、追加取得を記録する。検索による配布は判定ではなく参照候補である。
4. 原資料・規則・抽出・配布入力・最終根拠照合対象の変更を検知して再利用を停止する。既存出力への再実行で確認済み台帳を初期化しない。
5. 指摘の確定文を一つの台帳に保持し、03・04・05を生成する。既存文書は上書きせず、人手修正の照合を必要とする。
6. 担当別の全規則・全原文の確認記録、担当指摘の統合先、03→04→Wordの転記、期間評価、独立性、目視完了を検査する。確認工程を省略する設定は追加していない。
7. 常時参照するAGENTS.mdを短縮し、元の詳細規程を `docs/review_operating_contract.md` に保持した。標準実行は `docs/precheck_v3_workflow.md` とした。

## 作業フォルダとスキルの差の整理

| 対象 | 更新前の差 | 採用した処理 |
|---|---|---|
| precheck_scan.py | 作業フォルダは概要件数のみ。導入済みには事実候補・書式残骸検出があった | 導入済みの追加機能を作業フォルダへ統合し、担当別入力生成と再実行保護を追加 |
| precheck_verify.py | 作業フォルダは主に項目番号集合で照合。導入済みは指摘単位・期間評価・A/B全文照合を持っていた | 導入済みの検証を採用し、担当結果からの脱落・旧版入力・独立性の検証を追加 |
| Word生成 | 作業フォルダと導入済みでファイル名処理・事前検証等に差があった | 導入済みの52行・順序・フッター・ファイル名の検証を採用。公式テンプレートは変更しない |
| 規則・運用 | 全文読み込み指示と必要箇所だけ読む指示が混在 | 規則の意味内容は作業フォルダを正本に維持。標準手順をv3へ統一し、詳細規程を参照用へ移した |
| 利用量記録 | 取得不能時にも記録ファイルを生成できた | 明示依頼時だけ使用。取得不能時は新しい利用量ファイルを書かない。新担当名に対応 |

正本は作業フォルダの `tools/`・`rules/`・`docs/`、配布用は `codex-skill/`、導入済みは `<利用者が指定したスキル導入先>`。同期スクリプトで変更前のファイルを退避し、同一内容であることをハッシュで確認する。旧リリースの `github-export/` と過去の退避は実行元に用いず、この更新の同期対象には含めていない。外部への公開は実施していない。

```powershell
python tools/sync_precheck_skill.py --install <利用者が指定したスキル導入先> --check
```

## 検証

- 自動テスト：原文保持、全108規則の割当、例外保持、変更検知、キャッシュ再利用、未読・未照合・目視未実施の停止、指摘対象項目の脱落、過剰指摘防止、Word転記・正式名・テンプレート保持を確認。
- 独立担当によるコード・手順照合を実施。指摘された人間確認の脱落、対象項目の部分脱落、期間評価の再照合、規則の切替、非対応形式の無警告除外、品質資料への参照を修正した。
- 作業フォルダ・配布パッケージ・導入済みスキルの同期確認と、スキル形式検証を実施。
- 合成資料で導入済みスキルを別の作業ディレクトリから起動し、規則の自動選択、全108規則の生成、原文取得、同じ出力の再利用を確認。

検証記録は `outputs/efficiency-20261027/`。更新前の退避は同フォルダの `before/`、同期直前の個別退避は `outputs/skill-sync-*/`。

## 配布量の確認と未測定の事項

合成テキスト資料を使い、2担当へR1/R2/R3と原文全文をそれぞれ渡す場合の45,944文字と、担当別入力32,876文字を比較した。担当別入力は約28.4％少なかった。担当入力側には識別子・説明・機械抽出候補が含まれる。

この比較は2担当への初回入力だけであり、追加取得、親担当、編集、根拠照合、モデルのキャッシュ、出力トークンを含まない。実案件のトークン数・5時間枠の削減率・医学的判断の精度は測定していない。機械検証は意味内容の妥当性を保証せず、独立レビュー・目視・人間の最終判断を維持する。

実案件では同一資料・モデル・推論設定・成果物で比較し、親と各担当の最終累積入力・キャッシュ済み入力・出力を分けて記録する。既知の指摘の再現だけでなく、見落とし・過剰指摘も人間が確認する。数値の取得不能時は推測せず報告する。
