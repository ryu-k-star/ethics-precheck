# 過去事例の分類と使い方

このフォルダは、過去のプレチェック成果物を段階別に分類した索引である。実体ファイルは研究フォルダ内に置いたまま参照する。

> 2026-07-28 改訂。従前は6案件を無条件に「Gold Example」と呼んでいた。この呼称は、事例に載っていない論点を探さなくてよいという誤った許可を与える。品質の裏付けの度合いに応じて3段階に分け、現時点で第3層に認定した事例はゼロとした。

## 大原則

**過去の `99_プレチェック出力` は正解でも根拠資料でもない。** 対象研究の原資料を独立に確認し、`rules/R1`〜`R3` を全件適用したうえで、過去事例にない論点も探索する。過去事例の指摘数、指摘粒度、A/B/Cの配分を機械的に踏襲しない。

参照する順序を守る。

1. `rules/R1`〜`R3` を対象研究の原資料に適用し、指摘候補を確定する（工程2）
2. 04を書く（工程3前半）
3. **その後で**過去事例を開き、文体と分量を確認する（工程3後半）

事例を先に読むと、事例に載っている論点だけを探す方向に引きずられる。順序は逆にしない。

## 第1層 参考事例（品質保証なし）

`research-folder/` および `research-folder/プレチェック完了/` 配下の全ての `99_プレチェック出力`。

- 品質の再検証を行っていない。
- 見落としを含み得る。指摘の正確性は保証されない。
- 用途は、返却Wordの体裁とファイル構成の確認に限る。
- **指摘の採否判断の根拠に使わない。**

## 第2層 キャリブレーション事例（人間修正の内容と採否理由が記録されている）

AI初稿の後に人間が返却用Wordを修正し、その修正内容が `04_指摘事項書ドラフト.md` 冒頭の注記に記録されている事例。研究者へ実際に返却した版に整合している。

**保証されるのは「実務上採用された」ことであり、「網羅的だった」ことではない。** 追加の見落としがあった可能性は残る。

## 第3層 Gold Example（認定済み）

**現時点で該当なし。**

第3層として認定できるのは、次の全てを通過し、人間が明示的に承認した事例に限る。

| 条件 | 記録先 |
|---|---|
| 04の各指摘について、原資料の頁・項目根拠を再照合した | `06_ファクトチェック結果.md` の根拠照合表 |
| `rules/R1`〜`R3` を全ルール適用し、適用したが該当しなかったルールIDも記録した | `03_サブAI別レビュー結果.md` |
| 見落とし監査を実施し、追加すべき論点がないことを確認した | `06_ファクトチェック結果.md` |
| 過剰指摘監査を実施し、申請書に求める粒度として過剰な指摘がないことを確認した | `06_ファクトチェック結果.md` |
| 返却Wordと04の全52行が一致することを機械照合した | `06_ファクトチェック結果.md` の W-5・W-6 |
| 人間が明示的にGold認定した日付と担当者を記録した | 本ファイル |

認定にあたっては、後日の再申請で前回の見落としが判明していないかも確認する。同一研究の後続版で新たな指摘が追加されている場合、前版はGoldにしない。

### 認定候補

第2層 2-1 のうち、後続版で新たな指摘の追加がない事例が候補になる。ただし上記6条件の記録がまだないため、認定前に再監査が必要である。

## 注意

過去事例を丸写ししない。対象研究の資料に基づいて、同じ品質基準、同じ文体、同じ優先順位の付け方を再現するために参照する。

事例に載っていない論点は「指摘しなくてよい論点」ではない。
